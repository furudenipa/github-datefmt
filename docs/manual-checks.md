### 次回の確認項目

- コミット履歴の日付見出し、Projects 表形式の日付セル。
- Pull Request・Issue の一覧、PR の差分・コミット画面、Actions の実行詳細、通知、検索結果、プロフィール、ブランチ、タグ。
- 狭い画面幅や表示倍率変更時のはみ出し、長い日付・複数のタイムゾーン。
- Projects の日付の編集・保存、フィルター、画面遷移、表示更新との両立。操作によりデータを変更しないテスト手順を用意する。
- ツールチップ、キーボード操作、スクリーンリーダー、拡張機能の無効化と再有効化。

## 2026-11-10 追加確認

- コミット履歴の見出しは `Commits on 2026-11-01` などに変換されることを確認。リストの見出しとしての関連付けは維持。
- Projects 表形式は、表示中の Due と Created の両方で日付が `YYYY-MM-DD` に変換された。列名や列 ID は判定に使っていない。
- 変換後の Due セルを選択し Enter で日付選択画面が開き、元の日付が選択されていることを確認。Esc で変更せず閉じた後も日付表示が戻ることを確認。保存操作は未実施。
- セルの型を確実に識別できる共通属性が確認できず、表の特定の表示構造と日付文字列の組み合わせで変換する。同じ構造のテキスト欄が日付と同じ文字列を持つ場合は表示も変換され得る。

## 2026-11-10 列型とフォントの再確認

- 表示列の選択メニューに日付のアイコンがあることを確認。さらにページ内の `memex-columns-data` に列 ID と型があり、セルの列 ID に対応付けられることを確認した。従来の文字列のみの推測は廃止し、日付・作成・更新・クローズ型だけを対象とした。型情報がない場合は変換しない。
- Chrome に拡張機能を再読み込みし、Projects 表で Due と Created の変換を確認。GitHub の標準フォントと `tabular-nums` を使うよう変更後、`2026-11-30` と `2026-09-18` の表示幅はいずれも約 82.26px。
- この判定は GitHub の内部 DOM と列定義に依存する。GitHub 側の変更で型が取得できなくなった際は、表示が元のままになる。
